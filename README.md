# 墨影书城 · 一页一画

> **视觉体系 · 日系漫感 · 治愈纸漫**：暖白纸感基底 + 国漫朱砂红（#E85B3F）主色 + 天青（#2BA8C9）点缀，参考 B站 / 漫画台 / 腾讯动漫 / 爱奇艺 / 二次元软件（夏目友人帐、灵契、从前有座灵剑山、狐妖小红娘画风；番茄小说 / 七猫小说式阅读 UI；动漫体系按钮）；全站封面、场景插画、漫画分镜、头像均由程序化 SVG 生成，无外部图片依赖。

有画面感的小说 App（前端工程）。**普通小说、画面互动小说、漫画、动漫视频**四种读法；创作者上传作品（漫画支持自选图片、互动小说带画面人物），管理员后台审核授权、推流量，收益经管理员审核后结算提现。所有封面、场景插画、漫画分镜、头像均由程序化 SVG 生成，全站无外部图片依赖。

## 功能

- **四类作品**：普通小说（章节连载，14 类题材：仙侠/武侠/历史/游戏/言情/轻小说/都市/现实/悬疑/科幻/奇幻/青春/同人/衍生）、画面互动小说（场景插画 + 画面人物 + 剧情分支 + 多结局）、漫画（分镜页面 + 对话气泡，支持创作者自选上传图片）、动漫视频（仅管理员上传 mp4/webm，浏览器 IndexedDB 存储）
- **分类书城**：按类型（小说 / 互动 / 漫画 / 动漫视频）与题材筛选，编辑推荐（管理员推流量）、热门榜、新书上架、猜你喜欢
- **阅读器**：小说章节阅读、互动剧情引擎、漫画分镜阅读（自定义图片优先）、动漫视频播放；书币充值（可选充值方式：支付宝/微信支付/银行卡/云闪付，管理员可开关）、VIP 全免、章节订阅、打赏
- **书架 / 搜索 / 登录注册**：进度同步、最近阅读、账号体系（读者 / 创作者 / 管理员）；注册支持**账号 / 手机号（短信验证码）/ 邮箱**三种方式，登录支持账号密码与**微信 / QQ 第三方快捷登录**（演示环境自动注册演示账号）
- **读者隐私化**：隐私设置含 5 项开关（隐藏书币余额 / 隐藏最近阅读 / 隐藏书架 / 隐藏收支记录 / 隐身模式）+ **清除阅读历史**，全部实时生效并写入审计
- **意见反馈渠道**：读者提交功能建议 / Bug / 内容举报（附联系方式），管理员后台回复处理
- **客服站内信**：读者「联系客服」实时会话，管理员后台客服信箱回复（未读角标），消息全程安全扫描
- **创作者中心**：**开通创作者需提交资质审核**（资质说明 + 首部作品初步发布，管理员审核通过后自动开通并生成待审作品）；四类上传编辑器（章节 / 剧情节点含画面人物 / 分镜页含传图 / 动漫视频）、作品管理、收益中心、提现申请；上传作品需管理员审核通过后上架
- **用户等级**：六级（见习书虫 → 传奇书灵），发布/收入/收藏/VIP/登录均可获经验；高等级优质作品更易被管理员推荐流量
- **管理后台（安全码保护）**：首次进入设置 4 位以上安全码，连错 5 次锁定 10 分钟；数据概览、用户与等级（VIP 授权 / 等级调整 / 封禁解封 / 书币调整，操作全部审计）、资质审核（创作者开通审批）、作品审核（通过/驳回/下架/隔离/推流量）、收益结算审核、提现审核（含提现渠道审核）、**用户服务（意见反馈工单回复 + 客服信箱会话）**、安全中心（全站查杀/防篡改守护/操作审计）、全站设置（站名/公告/VIP 价格/充值汇率/分成比例/充值方式管理/开放注册）
- **收益保护流**：订阅/打赏 → 生成待结算单 → 管理员审核通过 → 进入创作者可提现余额 → **绑定提现渠道（支付宝/微信/银行卡，管理员审核通过后方可使用）** → 申请提现（冻结）→ 管理员确认放款或驳回退回（到账渠道快照固化），全程流水留痕 + 审计

## 安全体系

- **内容查杀**：全站文本扫描脚本注入 / javascript: / iframe / on* 事件劫持 / img onerror / eval / 存储探测 / DOM 直写 / svg onload / data: HTML 等危险载荷；发现即隔离作品（下架 + 清除内容 + 封禁作者）
- **防篡改守护**：所有数据写入附加哈希签名并同步 shadow 备份；读取校验签名，不匹配自动从备份恢复；每 30 秒自动巡检全库，跨标签页外部改写实时监控；修复次数/巡检时间在安全中心展示
- **入侵警告**：全站顶部横幅告警（数据篡改 / 病毒注入 / 暴力破解），危险内容标记实时统计
- **数据库护死**：签名失效且无有效备份的数据直接丢弃并记录日志，拒绝采用被篡改数据
- **金额交易**：充值（方式可选、汇率全站可配）/ VIP 价格 / 分成比例全站可配；收益结算单审核制；提现渠道审核 + 提现冻结式处理；金额变更全部写入流水与审计
- 注：以上为前端演示级防护（localStorage + IndexedDB + 哈希签名 + 混淆），真实生产环境需服务端鉴权与数据库层防护

## 数据说明

- 纯前端实现：业务数据保存在浏览器 localStorage（命名空间 `moying-novel`，每个键附带签名与 shadow 备份），首次访问自动写入种子数据（3 部小说、2 部互动小说、2 部漫画、1 部待审核作品）
- 上传的漫画图片与动漫视频存浏览器 IndexedDB（库 `moying-novel-files`），不占 localStorage 容量；建议视频用 mp4/webm、单文件 ≤200MB（受浏览器配额限制）
- 换浏览器 / 换设备数据不共享；API 层（`src/lib/api.ts`）以内存 + localStorage 模拟后端，接口命名贴近真实后端，便于日后接入服务端
- 付费模型：1 元 = 100 书币（可配置）；VIP 1800 币/月（可配置）；订阅分成 70%、打赏 100%、VIP 创作者分成 +10%

浏览器打开 `http://localhost:32100` 即可使用；`spark.json` 中可修改端口。

```bash

```

### 生产构建

```bash
npm run build
```

构建产物按两层输出（妙搭托管协议，见 `vite.config.ts`）：

| 目录 | 内容 | 部署位置 |
|------|------|----------|
| `dist/output/` | `index.html`、`public/` 静态资源、`routes.json` | 站点根目录（同源） |
| `dist/output_resource/` | `assets/` 下的 JS/CSS 构建产物 | 站点根目录（或 CDN） |

> 普通静态托管时，把 `dist/output/` 与 `dist/output_resource/` 两目录内容**合并部署到站点根**（即 `index.html` 与 `assets/` 同根），否则资源路径 `/assets/*` 会 404。

本地预览构建产物：

```bash
npx vite preview
```

### 部署到静态托管

本项目是纯前端 SPA（`BrowserRouter`），任何能托管静态文件的平台均可部署：

**Nginx**

```nginx
server {
  listen 80;
  server_name your-domain.com;
  root /var/www/moying;          # 合并后的 dist 产物根目录

  # SPA history 路由回退到 index.html（关键，否则刷新子页面 404）
  location / {
    try_files $uri $uri/ /index.html;
  }

  # 构建资源长缓存
  location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
  }
}
```

**GitHub Pages / Vercel / Netlify**

- GitHub Pages：推送源码后配置 Pages 构建命令 `npm run build`，发布目录 `dist/output`（如资源 404，改为发布合并后的目录）。
- Vercel：导入仓库，框架预设选 Vite，构建命令 `npm run build`，输出目录 `dist/output`，并添加 Rewrite `/(.*) → /index.html`（SPA 回退）。
- Netlify：构建命令 `npm run build`，发布目录 `dist/output`，并添加 `/* /index.html 200` 重写规则。

**部署在子路径（如 `https://host/moying/`）**

构建时注入路由基路径：

```bash
# Windows PowerShell
$env:MIAODA_CLIENT_BASE_PATH="/moying/"; npm run build
# macOS / Linux
MIAODA_CLIENT_BASE_PATH="/moying/" npm run build
```

> ⚠️ **数据边界（务必阅读）**：本项目为前端演示级架构，业务数据存于**各用户自己的浏览器**（localStorage `moying-novel` + IndexedDB `moying-novel-files`），上传的漫画/视频同样只存在本机浏览器。部署上线后**不同用户之间数据互不相通**（各自浏览器各自一份种子数据），且换设备不共享。若要实现真正的多人书城（多用户共享作品库、服务端审核与结算），需按 `src/lib/api.ts` 的接口形态接入服务端（鉴权 + 数据库 + 文件存储），前端无需大改。

### GitHub 云端内容库（仓库当数据库，可选）

应用支持把**共享书城内容库**（books / chapters / visualScripts / comicChapters / comicPages）存进 GitHub 组织 **22uuuc** 的仓库 `db/*.json`，实现跨设备同一份书城。组织仓库分工：

| 仓库 | 职责 |
|------|------|
| `22uuuc/6v` | 内容库 + 代码（本书城前端工程，`db/*.json` 为权威内容数据） |
| `22uuuc/moying-users` | 用户数据仓库（与内容/代码分离） |
| `22uuuc/moying-settings` | 全站设置数据库（站名 / 公告 / VIP 价格 / 充值汇率等） |



- **读者端**：每次打开应用都自动从固定渠道（连接写死于代码 `src/lib/cloud.ts` 的 `CLOUD_CHANNEL`，仓库组织 `22uuuc`）匿名增量拉取（`raw.githubusercontent.com`），云端为权威、失败静默保留本地种子数据；前端只读提取、无出口写入权限，所有推送仅限持令牌的管理员后端（代码层含管理员出口权限校验）；拉取内容同样经过内容查杀扫描。
- **管理员**：后台「云同步」面板配置 GitHub 令牌（fine-grained token，仓库 `Contents` 读写权限）后，可一键**从云端拉取**或**推送本地内容库到云端**；令牌混淆加密保存在本浏览器。
- **私有数据边界不变**：账号 / 余额 / 书架 / 订阅等仍存各用户自己的浏览器，云端只同步公开内容库。

```bash
# 本地导出当前内容库为 cloud-db/db/*.json（推送仓库前用）
node --experimental-strip-types scripts/export-cloud-db.mjs
```

> 令牌只用于向目标仓库推送，请按最小权限创建；GitHub 仓库内容库方案适合个人 / 小团队运维，生产级多租户仍需服务端数据库。



内容查杀、防篡改守护、数据库护死、金额审计等均为**浏览器端演示级防护**（哈希签名 + shadow 备份 + 混淆）。生产环境请务必补充：服务端鉴权与会话、数据库层防篡改与审计、HTTPS、支付与提现的真实第三方对接、服务端病毒/内容扫描。
